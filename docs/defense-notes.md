# 课程答辩说明

## 展示顺序（约5分钟）

1. 打开在线网页，说明经典下楼梯玩法和原生浏览器运行目标。
2. 试玩左右控制、尖刺、传送带、假平台、弹簧；暂停与重开。
3. 展示本机排行榜及设置，刷新证明持久化；说明没有后端或账号。
4. 展示核心测试与纯规则模块，解释单向连续碰撞：前后相对位置→穿越时刻→当时横向重叠→最早接触。
5. 展示固定seed、30/60/120渲染FPS确定性和平台回收测试。
6. 展示美术SVG与生成脚本、音频合成源代码、CI及提交历史。

## 自己实现的内容

独立重写规则核心、固定步长、相对运动碰撞、生成器、本地存档、中文响应式UI、触控、原创角色/平台/背景、表现动画、程序合成音频、自动化测试、Pages部署。没有直接复制iPel主程序或原作图片。

## 为什么不能说“完美原版”

iPel是模仿实现，不是4399官方源码。用户试玩指出难度低后，本项目核查同一4399页面提供的Flash文件，修正了普通/尖刺比例、横向移动能力和尖刺伤害。其余现代改动仍明确记录；原版的滚动标记计数与本项目参考序号计数不同。

## 关键问答

- 为什么不用Phaser？现有需求只有简单单向平台，独立Canvas核心更容易测试和校准，无需引擎物理拟合。
- 为什么物理120Hz而渲染60Hz？规则步长固定，不随屏幕帧率改变；渲染插值保持平滑。
- 为什么要seed？让测试、缺陷复现与概率分析可重复；表现粒子随机不参与规则。
- 为什么没有全球榜？首版明确只做本机记录，不增加账号、数据库与服务费用。
- 可达性等于必通关吗？不等于，只检查存在基础物理路线，不保证任何玩家位置或无伤路线。
- 自动化到100层能算通关吗？不能。事件测试与人工实际0—100层是独立验收项。
