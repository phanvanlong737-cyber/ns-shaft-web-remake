# 同一尖刺边缘重复扣血缺陷

用户报告：场地中间，同一尖刺平台首次扣血后左右移动，出现生命耗尽。优先级HIGH；在rc.6修复，旧版本仍包含该问题。

## 修复前复现

使用140 px/s滚屏，尖刺序号1、x=100、y=420，玩家x=120。首次落地后HP=5，原地推进130个120Hz物理步，使保护期结束。向右推进57步后x=200.75、y=175.83，仍在场地中间，却出现hurt(-5)、land(seq=1)、game_over(hp)，HP归零。向左离开边缘也有同类问题。

原因：横向离开先解除附着，但后续扫掠碰撞仍检测旧平台。穿越时间为0时使用移动前的横向位置，重新命中旧平台，重复执行尖刺onLand。先前2秒左右往返测试没有走出平台边缘，因此未覆盖这条路径。

## 修复

- 当步明确离开的平台不再参与当步落地检测，避免虚假重新附着及重复落地事件。
- 每块尖刺记录本局是否已实际造成伤害。同一块尖刺最多扣一次，离开再回来也不重复扣；另一块尖刺仍正常伤害。受保护而未实际扣血的接触不会提前消耗这次机会。平台随世界回收，新局重新生成，无历史引用累积。
- 新增左右边缘物理回归，以及同一尖刺再次落地/另一尖刺伤害回归。
- 浏览器复现同一输入序列，同时验证HP数值、五格血条、存活状态、结算界面隐藏，覆盖Chrome/Edge/Firefox/Chromium及手机模拟。

浏览器测试专用场景只在DEV与?test=1下启用，生产构建不包含该入口。顶部尖刺即死与底部坠落死亡仍按独立规则处理。
